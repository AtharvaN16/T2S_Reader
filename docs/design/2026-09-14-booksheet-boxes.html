The two boxes

“On this device” and the rendering block are the same object in two states, and neither is laid out like it. Four things are actually wrong — and only one of them is spacing.

Scope BookSheet.onDeviceBox and BookSheet.renderProgress
01 / WHAT'S OFF

Four faults, named

#FaultWhy it reads wrong
1The two boxes share nothing. One is title+size / count / pill. The other is title+percent / subtitle / bar / two pills. Different rhythms, different orders. They are the same object — this book's audio — in two states. Swapping between them redraws the whole block instead of changing a line.
2The header row is a heading, not a fact. “On this device” with 135.3 MB floated to the far right reads as a section title with a stray number. The size is the answer, and it is set in 13 pt grey — smaller and quieter than the question. The important thing is the least visible thing on the row.
3Nothing is drawn to scale. “9 of 23 chapters” is a ratio printed as words, with no bar — while the rendering box does have a bar, for a single chapter. The box that most wants a proportion doesn't have one; the box that has one is measuring the smaller thing.
4The controls hang off the bottom-left. One pill in a 14 pt padded box leaves a wide empty right half, so the box looks bottom-heavy and unfinished. This is the spacing complaint — but it's caused by a lone left-aligned pill, not by the padding value.
02 / FOUR FIXES

Each drawn in both states, so you can see them swap

A. It is the only one that fixes all four: one shape across both states, the size promoted to the thing you actually read, a bar that measures the book rather than one chapter, and controls on a full-width row so nothing hangs. The segmented bar is also honest in a way a continuous one isn't — chapters are discrete, and you can count what you have.

If 23 segments look too fine on a long book, the fallback is a plain bar at the same position — same layout, one view swapped.
